## Identity, state and API contracts

POST /api/line/webhook verifies the exact raw request signature before JSON parsing. Event IDs are required and processed in a single transaction. Follow/message commands record friendship, enqueue one welcome with a stable UUID retry key, and expose the configured LIFF URL; unfollow stops the binding. Ignore older friendship events. Official Account Manager greeting must be disabled manually before launch to avoid a second greeting; external configuration cannot be inspected without credentials.

POST /api/line/bind accepts id_token, account, password; validates LINE identity on the backend and checks a private enrolled account in local_research mode. Invalid requests count against IP and identity/account limits. No automatic registration or Docter+ fallback. Same LINE/study/member is idempotent; conflicts return 409. Successful transaction returns original bound_at and next-day Taipei 09:00 (or later existing study start). Binding does not grant staff access. GET /api/line/config exposes only LIFF ID and test-mode label to the dedicated page. No LINE state endpoints in ordinary navigation.

## Reminders

Run a separate externally scheduled worker once per minute. Backend defaults: 09:00–21:00 inclusive, 120-minute interval, 10-minute grace. The 21:00 cutoff is an adjustable default because no other evening cutoff was supplied. A study/member/date/HH:mm unique outbox key and fixed retry UUID identify each business job. Commit job intent before any HTTP call. Commit each attempt count and 60-second uncertain lease before HTTP. Reacquire a per-job transaction, verify lease ownership, re-read binding/diary and the clock after blocking reads, send with a ten-second HTTP timeout, and commit each result independently. A crash keeps the uncertain lease, attempt count, immutable payload and retry key. SQLite busy timeout is 45 seconds. Retry delays are 30/60 seconds; max three durable attempts. Retry the identical stored payload only; unknown timeout is not acceptance. 2xx or 409 with accepted-request-id means accepted by LINE, never delivered/read. Backoff for network/5xx, mark rate/quota 429 and permanent 4xx failed. Maximum three attempts, all within the original ten-minute window and same Taipei day. Expired pending work becomes skipped; no catch-up burst. Unfollow, inactive roster, ended study, archived participant, revoked invite or completed exact target diary cancels work. A submission racing a request LINE already accepted cannot recall that message.

Production diary adapter calls the private nsysu_private.line_diary_snapshot(member,date) through a dedicated backend capability role. The function checks private line_subjects enrollment, inclusive original study dates, participant archive status, exact sleep_logs.date and date_definition='wake_date', and the existing Vault invitation. Browser roles cannot execute it or read enrollment; the worker role cannot directly read Vault or diaries. The roster study assignment is unique per legacy member because baseline diaries do not have study IDs. Never create or rotate an invitation in the worker. No new study length. The original diary RPC remains authoritative for validation and submission.

## Resolved executable contracts (after independent audit)

Authoritative schema and exact columns/constraints are in backend/nsysu/sql/line_state.sql and the two new Supabase migrations. Import format, account grammar, API schemas/statuses, timestamp ordering, proxy handling, retry states/timeouts and deployment permissions are specified in docs/LINE_SETUP.md. Credentials use salted Werkzeug scrypt by default; fingerprints are SHA-256 of exact lowercase account strings. Disabled accounts stay in the registry with active=0, so uniqueness is retained. Invalid or duplicate roster import aborts atomically. First binding with no remaining eligible future date is rejected rather than displaying an impossible first reminder.

The reviewed local source was NSYSU_apple_design/backend/nsysu/auth_bridge.py and frontend/auth_bridge/index.html; only that isolated component was reused and its protocol rewritten. The website opens and records a dashboard WindowProxy. Only messages from that window or its immediate component frame, at the configured dashboard origin, are accepted. The component verifies its own parent render messages and exact opener source/origin; each request uses a new crypto.randomUUID nonce, consumed once and expired after 1.5 seconds. Every two seconds it reconciles the website session. Backend current user/role checks remain the authority. Session updates notify the Python component using session_updated; identity changes clear research caches. Logout invalidates outstanding frontend generations and clears participant names, histories, exports, QR image/title/link/cache and stored session. Subject query params, workspace selection and a separate _research_context preserve the operation through reauthentication.

Implementation checkpoints: schema/service synthetic suite first; website/session integration second; offline providers and real browser third; PostgreSQL privilege/rollback verification fourth; final build/lint/full regression and original-worktree hash audit last. Exact changed-file inventory is recorded by git status and summarized in docs/ACCEPTANCE_REPORT.md. No original computation modules or website-visit workflow are edited.
